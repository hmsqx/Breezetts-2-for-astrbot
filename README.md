# Breeze TTS 语音与歌曲翻唱（AstrBot 插件）

将本地 Breeze TTS 2 与 Seed-VC 翻唱接入 AstrBot，支持音色设计、参考音色克隆、普通语音回复，以及整首、高潮和指定片段翻唱。服务安装、启停、音色配置和歌曲管理集中在「语音服务」页面。

当前版本：**1.9.1** · 插件标识：`astrbot_plugin_breeze_tts`

## 功能

| 功能 | 说明 |
| --- | --- |
| 普通语音 | 注册 Breeze TTS Provider，可配合 AstrBot 自动 TTS，也可由 AI 按需调用 `speak` |
| 音色设计 | 使用文字描述声音、语气和语速 |
| 音色克隆 | 使用本机参考音频和对应原文，翻唱也使用当前参考音色 |
| 歌曲翻唱 | 支持整首、自动高潮、指定起止时间；默认连续发送多条 QQ 语音 |
| 歌曲库 | 联网收录、本地上传、查看和手动删除原始音源 |
| 可视化管理 | 普通 TTS 与翻唱独立启停，提供安装进度、歌曲任务状态和配置表单 |
| 一键安装 | 补齐配套后端、Python 依赖、音频工具和模型；支持下载源选择、重试及部分下载续传 |

普通 TTS 使用本机模型，不需要 Breeze Blue Developer API Key。歌曲收录保存原音源，翻唱通过声线转换保留旋律；「学歌」不会训练新的模型。

## 运行要求

当前版本面向以下环境：

- **Windows x64**，本机运行 AstrBot **4.29.3 及以上的 4.x 版本**。
- NVIDIA CUDA 环境；配套服务使用 Python **3.12**，可复用 AstrBot 自带解释器。
- 已验证 QQ / NapCat / OneBot v11；其他平台尚未验证。
- 本机存在可写的 **D 盘**。当前一键安装使用固定的 `D:/Echok` 服务目录，尚不支持自定义安装目录。

Linux、macOS、Docker 和远程服务托管未适配。模型生成速度、显存和磁盘占用取决于硬件、模型缓存与歌曲长度。

安装器首次预检要求普通 TTS 至少预留 16 GiB、翻唱至少预留 12 GiB 磁盘空间；检测到已有模型时至少检查 2 GiB。这是预检阈值，实际占用可能更高。

## 安装

### 1. 安装 AstrBot 插件

在 AstrBot 管理台选择 **插件 → 安装插件 → 从链接安装**，填写：

```text
https://github.com/hmsqx/Breezetts-2-for-astrbot
```

也可以从 GitHub 下载源码 ZIP，通过 AstrBot「从文件安装」导入。安装后在插件列表找到 **Breeze TTS 语音回复与歌曲翻唱**。

### 2. 安装并启动服务

1. 打开本插件详情中的 **「语音服务」** 页面。
2. 在「安装与下载来源」选择来源；通常先用「自动」。
3. 依次执行普通 TTS、翻唱服务的 **「一键安装」**。
4. 安装检查通过后，分别点击 **「启动普通语音服务」**、**「启动翻唱服务」**。
5. 先用 `/breeze_sample 你好，这是一段测试语音` 验证普通语音。

安装与服务启动是两个步骤。安装只准备文件和检查依赖，不自动加载模型或生成音频。重新修复安装前，请关闭两个服务并等待歌曲任务结束。

### 3. 设置音色

在「语音服务」页面填写并保存：

- **音色设计**：填写「音色描述」，参考音频路径与原文留空。
- **音色克隆**：填写参考音频的本机绝对路径，以及音频中实际说出的原文。
- **歌曲翻唱**：先设置可用的参考音频，作为目标声线。

参考音频应为完整的 **1–30 秒 PCM WAV**。例如 `D:/voice/reference.wav`；路径指向运行 AstrBot 的电脑，并非浏览器上传入口。歌曲上传入口用于收录歌曲音源。

如需将普通聊天自动转为语音，在 AstrBot 的 TTS 设置中启用并选择 Breeze TTS。只需要偶尔发语音时，也可以让 AI 调用 `speak`。

## 指令

| 指令 | 说明 |
| --- | --- |
| `/breeze_sample <文本>` | 用当前音色合成并发送语音；不填文本时使用默认测试句 |
| `/breeze_status` | 查看当前模式、服务地址、参考音频和歌曲任务状态 |

以上为默认 `/` 前缀下的用法。模型工具由 AI 调用，直接发送工具名称不会自动作为聊天指令执行。

## AI 工具

| 工具 | 作用 |
| --- | --- |
| `speak(text)` | 按当前音色合成并发送普通语音 |
| `set_voice_design(instruction, cfg_scale)` | 切换为文字设计音色，清空克隆音色设置 |
| `set_voice_clone(ref_audio_path, ref_text)` | 设置参考音色和准确原文 |
| `learn_song(name, url, artist="")` | 后台收录可获取的歌曲音频 |
| `list_learned_songs()` | 查看已收录歌曲 |
| `delete_song(name)` | 管理员明确要求后删除指定原始音源 |
| `sing_song(name, delivery="voice")` | 整首翻唱，默认发送连续语音 |
| `sing_song_clip(name, ...)` | 自动高潮或用户明确指定的时间片段翻唱 |

如果模型不调用工具，请确认当前模型支持工具调用，且当前人格允许使用对应工具。音色设置会持久化保存，参考音色路径应指向可信的本机文件。

### 使用示例

| 对 AI 说 | 对应行为 |
| --- | --- |
| 「用语音说：今天辛苦了。」 | 调用 `speak` |
| 「查看你已经学过的歌。」 | 列出歌曲库 |
| 「唱完整首《歌名》，用语音发给我。」 | 整首翻唱，按自然停顿发送多条语音 |
| 「唱周杰伦《反方向的钟》的高潮。」 | 使用明确歌手辅助查询，由当前会话模型选择完整副歌 |
| 「唱《歌名》第 90 秒到 160 秒。」 | 指定范围，无需在线同步歌词 |
| 「把整首《歌名》的翻唱作为文件发给我。」 | 整首翻唱并发送音频文件 |

手动范围示例：

```json
{
  "name": "sing_song_clip",
  "arguments": {
    "name": "歌名",
    "start_seconds": 90,
    "end_seconds": 160
  }
}
```

**整首 / 片段决定音频范围，语音 / 文件决定发送方式，两者独立。**

- 默认 `delivery="voice"`，整首也会发送多条语音；只有明确选择 `file` 才发送文件。
- 语音按检测到的人声停顿切分，不固定每 15 秒切一刀。
- 单条语音最多 60 秒，20–45 秒只是偏好；必要时允许较短首尾段。
- 没有安全切点时，会在发送分段前报错，不切断唱词，也不自动改发文件。
- 收录与翻唱任务异步执行；工具返回「正在准备」不代表已经生成或发送成功。

## 歌曲库

在「语音服务 → 歌曲库」中可以上传、查看和删除音源。

- 支持 WAV、MP3、M4A、AAC、FLAC、OGG、OPUS、MP4 和 WebM。
- 页面单文件最多 **120 MiB**，音频最长 **10 分钟**。
- 可填写歌名、实际歌手和语言；上传后校验、转换为后台可用格式。
- 原始音源永久保留，只有明确手动删除才移除；临时翻唱成品按清理规则处理。
- 页面删除需确认完整歌名；上传、识别或翻唱任务进行中禁止删除。

联网收录需要 AI 先找到可访问音源或受支持页面，再调用 `learn_song`。若来源仅提供试听，收录的也只是试听音频。同名歌曲会提示复用；已知歌手冲突时，应改用包含歌手或版本的名称。

### 自动选高潮

自动高潮依次尝试 **LRCLIB → 网易云公开歌词 → 当前音源的本地 CPU 识别**，再交给当前会话模型选择连续歌词范围。

匹配会校验曲名、歌手、语言、录音版本和时长，避免将现场版、翻唱版或不同语言版本的歌词直接套用。提供准确歌手和版本，有助于匹配。

本地识别在临时 CPU 子进程运行，结束后释放内存；识别结果按音源身份与语言缓存。识别或模型判断仍可能有误，无法得到可靠范围时，请指定起止时间。整首与手动时间范围不依赖同步歌词。

## 配置

可在 AstrBot 插件配置或「语音服务」表单中修改；两处使用同一份设置。保存影响后续请求，不自动启停服务。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `instruction` | 年轻女性、柔和偏低的音色描述 | 用于设计音色，也可作为克隆时的语气引导；可留空 |
| `cfg_scale` | `4.0` | 范围 1–10；纯克隆或无描述时实际使用 1.0 |
| `seed` | `42` | 随机种子；相同参数可减少波动，不保证结果完全一致 |
| `ref_audio_path` | 空 | 参考音频本机绝对路径 |
| `ref_text` | 空 | 参考音频中实际说出的原文；克隆时必填 |
| `clone_use_instruction` | `false` | 克隆时是否同时使用文字语气引导 |
| `api_base` | `http://127.0.0.1:7860` | 普通 TTS API 地址 |
| `timeout` | `120` | 单项网络操作超时秒数 |
| `max_retries` | `3` | 最多请求次数，包含首次请求 |
| `singing.enabled` | `true` | 启用歌曲翻唱 |
| `singing.api_base` | `http://127.0.0.1:7861` | 翻唱 API 地址 |
| `singing.timeout` | `1800` | 翻唱单项网络操作超时秒数 |

服务控制按钮只管理当前支持的本机服务和默认端口。其他入口修改了配置时，页面会拒绝用旧版本覆盖，请刷新后重新编辑。

### 安装下载源

页面分别提供 **Python 依赖、CUDA / PyTorch、模型权重**三个选择器。

- 自动模式：按安装器配置依次尝试可用来源，并显示当前来源与重试信息。
- 手动指定：只使用选择的来源，失败后由你重新选择。
- 选择保存在当前浏览器，开始安装时固定到该次任务，不改系统 pip 配置。
- 中断后可点击「继续安装 / 修复」；通过校验的文件会复用，已知大小的部分下载支持续传。

依赖可选择清华、阿里云和官方源；CUDA 依赖提供阿里云、交大及官方来源；模型可选择 Hugging Face 官方或国内镜像。换源不能解决磁盘不足、驱动、DLL 和依赖版本冲突，请查看实际错误。

## 服务与临时文件

普通 TTS 和翻唱共用有限的显卡资源。进入 GPU 翻唱阶段时，普通 TTS 暂停，结束或失败后尝试恢复；本地时间轴识别不暂停普通 TTS。

| 内容 | 位置 / 处理方式 |
| --- | --- |
| 插件配置 | `AstrBot/data/config/astrbot_plugin_breeze_tts_config.json` |
| 原始歌曲 | `D:/Echok/breeze-cover/data/songs/`，只手动删除 |
| 临时语音 | AstrBot 临时目录中的 `breeze_tts_*.wav`；保留最新 50 个，额外且超过 24 小时的旧文件会清理 |
| 模型与服务 | 位于 `D:/Echok` 下的配套服务目录；不会上传至本仓库 |

从插件启动的服务由 AstrBot 生命周期托管：退出 AstrBot 时关闭，插件热重载时保留；独立启动后被插件复用的服务保留外部归属，页面会显示。关闭管理网页不等于退出 AstrBot。

已确认发送成功的语音分段不会因后续失败而自动重发。

## 数据与隐私

普通 TTS 将文本及所需参考音频发送到配置的本机服务。模型、参考音色和原始歌曲保存在运行服务的电脑上。

安装会访问依赖与模型下载来源；联网收录会访问提供的音源页面。自动高潮会查询公开歌词，并将歌词或识别文本交给当前会话模型分析；是否发送到云端，取决于你使用的模型服务。

请仅上传或收录你有权使用的音频。使用云端模型、下载来源或其他外部服务时，请同时了解相应服务的数据处理方式。

## 常见问题

| 现象 | 排查方式 |
| --- | --- |
| 插件装好了，但不能说话 | 在「语音服务」安装并启动普通 TTS；自动语音还需在 AstrBot TTS 设置中选择 Breeze |
| 找不到「语音服务」页面 | 确认安装了完整插件包，并使用支持插件可视化视图的 AstrBot 版本 |
| 安装按钮不可用 | 检查是否有运行中的服务、歌曲或安装任务；修复安装前关闭两个服务 |
| 下载失败或速度很慢 | 在页面换源或恢复自动，查看最后一条实际错误，再继续安装 |
| 提示 Python / CUDA / DLL 错误 | 使用 Python 3.12，检查 NVIDIA 驱动及 VC++ 运行库；不要把依赖导入成功当作 GPU 推理已验证 |
| 提示目录或磁盘空间不足 | 当前安装依赖 D 盘的固定目录；检查写权限和可用空间 |
| 连接 `7860` / `7861` 失败 | 对应服务尚未启动或已退出；分别刷新状态并查看服务日志 |
| 无法克隆音色 | 使用完整的 1–30 秒 PCM WAV，填写准确原文，确认路径在运行 AstrBot 的电脑上 |
| AI 不调用翻唱工具 | 确认模型及当前人格允许工具调用，并先收录歌曲 |
| 找不到匹配同步歌词 | 补充歌手与版本；自动模式会尝试本地识别，也可直接指定时间或唱整首 |
| 找不到可靠语音切点 | 明确要求以文件发送，或选择有自然停顿的片段 |
| 翻唱期间普通 TTS 不回应 | GPU 转换阶段会暂停普通 TTS；任务结束后检查其恢复状态 |
| 已生成音频但 QQ 没收到 | 查看分段投递结果及 NapCat 日志，检查登录、OneBot 连接、FFmpeg 与语音转换错误 |
| 保存配置发生冲突 | 刷新页面后重新修改，避免覆盖其他入口刚保存的设置 |

## 项目结构与开发

```text
main.py                    AstrBot 注册入口、工具和生命周期
_conf_schema.json          插件配置定义
metadata.yaml              名称、版本与仓库信息
breeze/
  settings.py              配置读取、校验与持久化
  task_state.py            歌曲任务状态与 TTS 暂停协调
  tts_provider.py          普通语音 Provider 与音频校验
  dashboard.py             管理页面 API
  singing/                 歌库、选段、翻唱和语音分发
  services/                服务启停、一键安装与换源
views/service/             AstrBot「语音服务」页面
runtime/                   随插件携带的后端源码与许可证
tests/                     离线测试及页面交互检查
scripts/                   后端源码打包工具
docs/                      架构说明与变更记录
```

开发环境需要可导入 AstrBot。源码方式可通过 `ASTRBOT_SOURCE` 指定其根目录：

```powershell
$env:ASTRBOT_SOURCE = "C:/path/to/AstrBot"
python -m unittest discover -s tests -p "test_*.py" -q
python tests/test_service_web.py
node tests/test_service_view.cjs
```

测试覆盖配置、音频校验、歌词匹配、工具调用、安装恢复、换源、权限和管理页交互，不需要真实生成歌曲或向 QQ 发送消息。实际 GPU 推理、驱动和真实平台投递仍需在目标环境验证。

详细说明见 [开发架构](docs/ARCHITECTURE.md) 与 [版本记录](docs/CHANGELOG.md)。
